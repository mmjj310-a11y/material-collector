# 首次配置问答

分三轮收集信息。已有明确答案的不要重复问；每轮给简洁选项，允许自由输入。只检查被选择的目标，不要求用户安装所有软件。

## 第一轮：收什么，从哪里收

1. 想收集什么主题，用来做什么？
2. 有指定网站吗？可以提供网址，也可让 Agent 提出候选清单再选择。
3. 希望保留图片、文章链接与摘要，还是两者？需要哪些语言、时间范围和排除项？

默认建议：图片 + 来源链接 + 摘要，单次最多 10 条，先试采 3 条；这些是可修改建议。未提供或选定来源时不开始全网采集。不预置作者的站点列表。

## 第二轮：存在哪里

- 仅本地文件夹
- Obsidian
- Eagle
- Obsidian + Eagle

所有模式都需要一个本地工作目录保存索引和接手信息。Eagle 单独模式也保留工作目录，便于断点恢复；不要求安装 Obsidian。

Obsidian 模式：在用户指定 Vault 下新建专属子目录，不把初始化脚本指向已有 Vault 根目录，不覆盖旧文件。仅创建 Markdown 文件不等于已在 Obsidian 中查看成功。

询问“是否同步到你自己的飞书？”默认关闭。开启时确认目标文件夹/文档/多维表格和内容范围：摘要与来源、精选附件、或本批全部入选资料。获取目标由相关连接器完成，不让用户把 token、cookie 或密钥写进问卷。用户没有选择共享范围时不改变权限。

## 第三轮：如何持续

确认手动或定期、时区、运行频率、每次条数和筛选标准。只在有宿主调度能力且用户已选择时设定任务；缺少能力时不能声称后台会运行。

展示精简配置摘要后，按用户已作的选择创建配置，无需反复索要同一授权。从 `assets/config.example.json` 复制并填写，路径和真实来源只写到用户工作区，不改技能内模板。配置与凭据分离。

配置放到目标目录之外的临时文件，用 init 创建尚不存在的新工作目录。以 1—3 条资料试采；报告图片/笔记可读性、查重和目标回读结果。若用户要导入旧库，先做独立迁移方案，不直接把旧库当空库初始化。

## 来源记录格式

`sources` 为对象数组，每项使用 `name`、`url`、`enabled`、`access_status` 四个字段。例如 `{"name":"用户选择的站点","url":"https://example.org/","enabled":false,"access_status":"unverified"}`。示例不启用，只有用户选择后才设为 true。访问失败仅更新状态及原因，不擅自停用。

`topics`、`filters.exclude` 与 `filters.languages` 为字符串数组；`schedule.timezone` 填用户指定的时区，未指定则询问或读取当前环境后告知。`destinations` 的库位置和飞书目标使用用户实际选项，空值不构成授权。
